# EXmodel — прогнозирование возникновения лесных пожаров

ML-пайплайн для оценки вероятности возникновения лесного пожара в ячейке
пространственной сетки на заданную дату, а также краткосрочного прогноза
(на 1 день вперёд) для пилотного региона.

Проект решает задачу **бинарной классификации**: `is_fire = 1` (пожар в
ячейке в этот день) / `0` (пожара нет).

## Возможности

- Загрузка и очистка реестров лесных пожаров за несколько лет из Excel.
- Парсинг координат в различных текстовых форматах (`64°20'24"N`, `64.34` и т.д.).
- Привязка пожаров к сетке ~1×1 км (шаг `0.01°`).
- Подгрузка метеоданных из **NASA POWER** (температура, влажность, ветер, осадки).
- Feature engineering: календарные признаки, точка росы, индекс `kp_daily`,
  лаги и скользящие средние по ячейкам.
- Отбор отрицательных примеров (negative sampling) для дисбаланса классов.
- Обучение и сравнение моделей **LightGBM** и **CatBoost**.
- Выбор лучшей модели по ROC-AUC и прогноз на будущее.

## Как это работает

1. **Загрузка пожаров** (`data/loader.py`) — читаются все `.xls/.xlsx` по
   паттерну `FILES_PATTERN`, ищется строка заголовка, нормализуются регион,
   дата, координаты, порода и тип покрова.
2. **Привязка к сетке** (`features/grid.py`) — координаты через `floor`
   переводятся в `grid_id` вида `широта_долгота`.
3. **Внешние данные** — метео из NASA POWER (`data/meteo.py`) и
   лесохозяйственные данные из реестра (`data/forest.py`).
4. **Датасет** (`features/engineering.py`) — отрицательный сэмплинг
   (`negative_ratio` не-пожаров на 1 пожар), признаки погоды, календаря,
   лагов (`1, 3, 7, 14`) и скользящих средних (`3, 7, 14`).
5. **Обучение** — LightGBM и CatBoost, разбиение **по времени**
   (прошлое → train, будущее → test), ранняя остановка по AUC.
6. **Сравнение** — метрики на тесте (ROC-AUC, F1, Precision, Recall).
7. **Прогноз** (`forecast.py`) — лучшая модель строит прогноз на 1 день.

Поддерживается фильтр по пилотному региону (`PILOT_REGION`, по умолчанию
«Республика Карелия»); если данных по нему нет — используются все данные.

## Используемые модели

Обучаются две модели градиентного бустинга:

| Модель   | Файл                      | Параметры            |
|----------|---------------------------|----------------------|
| LightGBM | `models/train.py`         | `config.MODEL_PARAMS` |
| CatBoost | `models/train_catboost.py`| `config.CATBOOST_PARAMS` |

**Лучшая модель выбирается по ROC-AUC** (`main.py`):

```python
if metrics_cb['roc_auc'] >= metrics_lgb['roc_auc']:
    best_name, best_model = 'CatBoost', model_cb
else:
    best_name, best_model = 'LightGBM', model_lgb
```

Остальные метрики считаются, но на выбор не влияют. Порог бинаризации
подбирается по максимуму F1 на тесте, ранняя остановка — по AUC.

Пример сравнения из последнего запуска (`run.log`):

```
Модель         ROC-AUC        F1   Precision    Recall
LightGBM        0.9760    0.8022      0.7175    0.9095
CatBoost        0.9780    0.8138      0.7626    0.8724

Для прогноза выбрана модель с лучшим ROC-AUC: CatBoost
```

## Установка

```bash
cd forest_fire_prediction

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

pip install -r requirements.txt
```

Зависимости: `pandas`, `numpy`, `lightgbm`, `catboost`, `scikit-learn`,
`openpyxl`, `xlrd`, `requests`.

## Запуск

```bash
python main.py
```

Путь к реестрам пожаров задаётся в `config.py` или через переменную окружения:

```bash
export FIRE_FILES_PATTERN="/path/to/Реестры лесных пожаров за 10 лет/*.xls*"
python main.py
```

## Настройки (`config.py`)

| Параметр                | Назначение                                             |
|-------------------------|--------------------------------------------------------|
| `FILES_PATTERN`         | паттерн файлов с реестрами пожаров                     |
| `PILOT_REGION`          | пилотный регион (`None` — все данные)                  |
| `GRID_SIZE_DEG`         | размер ячейки сетки в градусах (`0.01` ≈ 1 км)         |
| `TEST_SIZE`             | доля теста при разбиении по времени (`0.2`)            |
| `NEGATIVE_RATIO`        | сколько «не-пожаров» на 1 пожар (`5`)                  |
| `MODEL_PARAMS`          | гиперпараметры LightGBM                                |
| `CATBOOST_PARAMS`       | гиперпараметры CatBoost                                |
| `EARLY_STOPPING_ROUNDS` | число раундов ранней остановки                         |
| `CLASSIFICATION_THRESHOLD` | порог по умолчанию, если не удалось подобрать по F1 |
| `CATEGORICAL_FEATURES`  | категориальные признаки (`forest_type`, `forest_cover`)|

## Выходные файлы

| Файл                              | Содержимое                                             |
|-----------------------------------|--------------------------------------------------------|
| `fire_predictions_grid.csv`       | результаты теста LightGBM                              |
| `fire_predictions_grid_catboost.csv` | результаты теста CatBoost                           |
| `future_forecast.csv`             | прогноз на 1 день (лучшая модель)                      |
| `run.log`                         | лог запуска (метрики, важность признаков)              |

Колонки результатов обучения: `grid_id`, `date`, `is_fire`,
`predicted_probability`, `predicted_class`.
Прогноз (`future_forecast.csv`) содержит погодные и производные признаки и
колонку `predicted_probability`.

## Требования к входным данным

Excel-реестры должны содержать (поиск по названию колонки):

- `Субъект` — регион;
- `Обнаружен...` — дата;
- `Широта`, `Долгота` — координаты;
- `Порода` — тип леса (опционально);
- `Покров` — тип покрова (опционально).

## Ограничения / заметки

- Метеоданные NASA POWER загружаются по одной точке на ячейку — при большом
  числе ячеек загрузка занимает заметное время (есть пауза между запросами).
- В прогнозе на будущее лаги и скользящие средние заполняются нулями, так как
  истории на будущие даты нет.
- `elevation` в текущей версии — заглушка (`0.0`).
- CatBoost ожидает категориальные признаки как строки, LightGBM — как
  `category`; это учитывается при обучении и прогнозе.
